neo4j是一种NoSQL无表数据库,基于图论,处理实体-关系的图形数据结构速度快
知识图谱是一种语义网络: LPG 和 RDF 
默认就自带一个 neo4j 库，服务一启动就存在
LPG: 标签属性图
RDF: 资源描述图

Graph RAG: 传统向量 RAG 的升级范式,核心是把原始文档抽取为 实体-关系 知识图谱,融合「向量语义检索 + 图结构遍历推理」双能力给大模型提供上下文

Cypher neo4j专属的一个查询语言 简称CQL
eg: (fox)<-[:KNOWS]-(周瑜)-[:KNOWS]->(诸葛亮)-[:KNOWS]->(fox)
eg: (elementVar:Tag {key: "value"}) 

基本讲解:
一串节点+关系连起来的链条称为路径
路径中关系数量表示路径的长度
Cypher中字符串使用双引号或单引号表示都可以
变量可以给结点/关系取名字,用于引用属性数据,非强制需要 
elementVar: 结点变量 
relationVar: 关系变量
:LabelName 表示标签 eg: node:LabelName1:LabelName2 表示node同时拥有两个标签
:RELATION_TYPE 表示节点之间的关系类型 eg: (fox)-[:KNOWS]->(周瑜)
- 表示无向关系 eg: -[e:knows]- 带有属性和关系类型的无向关系
--> 或 <-- 表示有向关系 中间可插入关系类型 没有关系类型则任何关系都会匹配到相关节点
{key: value} 字典表示对节点或关系的描述即属性 不带空格/中文/中横线的键名不用引号,否则使用反引号
AS 别名 词若无空格/中文/中横线则不用引号否则使用反引号
element: 冒号前面的一般表示变量  
() 表示节点

MATCH (node) RETURN nodeVar 
MATCH (node) OPTIONAL MATCH (node) RETURN nodeVar1, nodeVar2 相当于SQL的LEFT JOIN,匹配不到返回null
MATCH (node) WHERE nodeVar.property = "value" RETURN nodeVar 条件查询

# pip install graphdatascience 下载GDS驱动 不同于 neo4j驱动 
from graphdatascience import GraphDataScience 

gds = GraphDataScience("bolt://localhost:7687", auth=("neo4j", "password"))

# 投影 res['nodeCount'] 获取结点数 res['relationshipCount'] 获取关系数
G, res = gds.graph.project("graph", "*", "*", {"orientation": "UNDIRECTED"}) # 名称 结点 关系 强行转无向图

# 执行 Louvain社区算法 并且 将数据写回neo4j
result_write = gds.louvain.write(G, writeProperty="community_id")
# result_write["communityCount"] 获取发现社区数
# result_write["modularity"] 获取模块度 --> 越接近1则分得越好  

G.drop() # 释放内存
