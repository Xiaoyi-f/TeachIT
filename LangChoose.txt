1. IO 密集（等东西）
程序大部分时间在干等，不用 CPU 干活：
等数据库返回数据、等调用 AI 接口、等读文件、等用户上传图片、等网络响应。
CPU 全程闲着发呆，只是等别人给结果。

2. 计算密集（使劲算）
程序全程疯狂压榨 CPU：图片批量修图、大数运算、视频转码、本地跑大模型、几万条数据循环复杂计算。
全程 CPU 满负荷运转，一点不闲着。

一、先回答你第一个疑问：Node 单线程弱，为啥 IO 密集它反而最强？

举个生活例子
饭店只有 1 个服务员（Node 唯一主线程），10 桌客人同时点单：
Java/Python 老式同步写法（一桌配一个服务员 = 一线程一连接）
来一桌客人，专门派一个服务员全程盯着等菜。10 桌就要 10 个服务员，人多了饭店装不下、工资成本爆炸。菜没做好的时候，这个服务员只能原地干等，啥也干不了。
Node 的事件循环（单服务员搞定所有桌）
就 1 个服务员，客人下单后直接丢给后厨（IO 操作：数据库 / 网络），服务员不用站那等，转头立刻接待下一桌客人。
后厨做好菜主动喊服务员，服务员再回来上菜。
等待的空档全部利用起来，不用额外雇人（开线程），人再多也不怕。

Node 所谓 “线程弱” 是什么意思？
Node 主线程只有 1 条，一旦 CPU 疯狂计算，服务员被拖住，所有客人都没人接待，直接卡死。
但 IO 场景 99% 时间都是等后厨，服务员完全有空接待别人，所以 IO 场景无敌。
Node 底层藏了 4 条备用小线程，只用来干文件读写、加密这种杂活，不处理用户请求。

二、三大语言：Java / Python / Node.js 什么时候该用谁？分场景讲死

场景 1：纯 IO 密集项目（90% 日常开发：网站、小程序后端、AI 接口、管理后台、聊天服务）
首选：Node.js
理由：
单线程事件循环天生处理海量等待请求，一台低配小服务器能扛上万用户，内存占用极低；
前后端都写 JS，一套语法，前端转后端零学习成本；
做实时聊天、WebSocket、AI Agent（你学的 pi 框架）、接口服务天花板；
短板：但凡有大量复杂计算，直接卡死。
次选：Python（异步 FastAPI/Sanic）
Python 普通 Flask/Django 是老式 “一桌一个服务员”，并发差；但异步框架和 Node 逻辑一样，也能扛高并发。
适合：你本来就会 Python，简单小接口、小工具。
不推荐 Java
Java 要开大量线程处理连接，吃内存，小服务器扛不住，写代码繁琐笨重，IO 场景性价比极低。

场景 2：纯计算密集（图片处理、数据分析、本地大模型、批量运算）
首选：Python（多进程）
Python 普通线程有 GIL 锁，同一时间只能 1 个线程用 CPU，多线程算东西不会变快。
但是多进程每个进程独立 CPU 核心，几核 CPU 就能同时分几份计算任务，多核拉满。
比如批量修 1000 张图片，开 8 进程 8 个 CPU 一起算，速度翻 8 倍。
次选：Java
Java 无 GIL，多线程就能多核并行计算，性能很强，适合大型商业计算系统。
绝对避开 Node.js
Node 只有 1 条主线程，一旦进入循环计算，整个服务卡死，所有用户全部卡住，没有任何办法。
如果非要用 Node 做大量计算，只能拆出去单独开子进程，麻烦到爆炸。

场景 3：大型企业复杂后台、高稳定金融 / 支付系统、超大并发业务
首选 Java
多线程成熟稳定，计算、IO 两头都能打；
内存管理、并发锁、分布式工具完善，不会轻易崩；
银行、电商、大厂核心服务全是 Java；
缺点：重、代码多、小项目浪费服务器资源。
不选 Node/Python
Node 扛不住超复杂混合业务；Python 运行速度天生慢，高流量容易卡顿。

场景 4：简单脚本、自动化工具、本地小工具
首选 Python
语法最简单，写爬虫、本地文件处理、小工具几行代码搞定。

场景 5：实时应用、聊天、AI Agent、小程序接口、前后端一套开发
首选 Node.js
你现在学的 pi-coding-agent 就是这个场景，完美适配。

三、一句话分清线程、进程该什么时候用（通用所有语言）
只要任务是等待（IO 密集）→ 用多线程 / Node 单事件循环
任务大部分时间在等，不用占用 CPU，线程轻量、开销小，不用开笨重进程。
Java/Python 同步框架：多线程处理连接；Node 不用多线程，单线程事件循环就能搞定海量 IO。
只要任务疯狂耗 CPU（计算密集）→ 必须多进程
Python：线程被 GIL 锁住，只能多进程才能多核加速；
Java/C++：多线程也能计算，但进程隔离更好，一个任务崩不影响整体服务；
Node：主线程不能算，只能单独开进程丢计算任务。

性能指标: 
1.响应时间: 从发起请求到收到完整结果一共花多久
2.并发数: 同一时刻同时向系统发起请求、正在使用系统的虚拟 / 真实用户数量
3.吞吐量: QPS：每秒查询 / 请求数  TPS：每秒事务数
4.点击数和错误率: 测试周期内总共发起的请求总量和这其中请求失败的数量 
5.资源利用率: 服务器硬件 / 中间件资源被占用的比例

黑盒测试: 测试人员依据需求文档把被测软件当成一个“打不开的黑箱子”，完全不看内部代码和逻辑结构，只通过输入数据，验证输出的结果是否符合预期
白盒测试: 开发团队依据源代码把被测软件当成一个“透明的玻璃盒子”，完全依据内部代码逻辑、数据结构、分支条件和执行路径来设计测试用例，验证程序的内部操作是否符合设计预期
--> 语句覆盖测试(保证代码执行)、分支覆盖测试(保证分支代码执行)、条件覆盖测试(保证条件代码执行)、路径覆盖测试(保证代码各种路径执行)

开店算法:
1.固定成本计算
租金 -> 成本
人工 -> 成本
水电费 -> 成本
2.计算保本点 
保本点 = 固定成本 / 毛利率 
Tip: 建议保证毛利率在60%~75%
Tip: 毛利率 = (销售额 - 仅仅材料进货成本) / 销售额 * 100% 
3.毛利率达成定价公式
定价 = 仅仅材料进货成本 / (1 - 毛利率)
