正向索引: 利用索引关联对应的数据 
倒排索引: 标记对应的数据的词条所在的索引 -- 根据词条搜索(速度快) -- elasticsearch 关键 

mysql 擅长事务类型操作, 确保数据安全和一致性 
elasticsearch 擅长海量数据的搜索、分析、计算 
通常将elasticsearch与mysql结合使用 

Elasticsearch自带标准分词器依据Unicode文本分割法(将特殊字符/标点分号对文本进行分割)

Elasticsearch的关键就是倒排索引，而倒排索引依赖于对文档内容的分词，而分词则需要高效、精准的分词算法，IK分词器就是这样一个中文分词算法
--> IK分词器、Kibana 均需同 elasticsearch 版本统一 
--> 安装命令可以直接问Ai 
--> IK分词器支持 ik_smart 模式, ik_max_word 模式

Index就类似数据库表，Mapping映射就类似表的结构。我们要向es中存储数据，必须先创建Index和Mapping
Mapping --> 对索引库文档的约束, 常见Mapping属性:
type: 
  text keyword --> 仅text参与分词 
  byte short integer long float double 
  boolean 
  date 
  object 
index: 是否创建索引, 默认值为true 
analyzer: 分词器 
properties: 该字段的子字段 

Tip: 索引等价于mysql表, 映射等价于mysql表结构(字段声明) 映射确定好之后就不要再改动 

创建索引库和映射:
PUT /索引库名称 
{
  "mappings": {
    "properties": {
      "key": {
        "type": "text",
        "analyzer": "ik_smart",
        "index": true, 
        "properties": {
          "sub_attr": {
            "type": "text",
            "analyzer": "ik_smart"
          }
        }
      }
    }
  }
}

// 倒排索引结构虽然不复杂，但是一旦数据结构改变（比如改变了分词器），就需要重新创建倒排索引，这简直是灾难。因此索引库一旦创建，无法修改mapping
// 允许添加新的字段到mapping中，因为不会对倒排索引产生影响，所以修改索引库能做的就是向索引库添加新字段, 或者更新索引库的基础属性

      "analyzer": "ik_smart",
      "index": true,
      "properties": {
        "sub_attr": {
          "type": "text",
          "analyzer": "ik_smart"
        }
      }
    }
  }

// 定义文档实体类 
@Document(indexName = "articles", createIndex = false) // 不让应用启动时自动建索引，生产用迁移脚本管
public class Article {

    @Id
    public String id;                 // 文档主键，对应 ES 的 _id

    @MultiField(
        mainField = @Field(type = FieldType.Text, analyzer = "standard"),
        otherFields = @InnerField(suffix = "raw", type = FieldType.Keyword))
    public String title;              // 标题：title 用来全文搜索，title.raw 用来排序/聚合

    @Field(type = FieldType.Text)
    public String content;            // 正文，补充召回

    @Field(type = FieldType.Keyword)
    public String category;            // 分类：精确过滤/分组

    @Field(type = FieldType.Keyword)
    public String status;              // 状态：published / draft，精确过滤

    @Field(type = FieldType.Long)
    public Long score;                 // 分数，long 存整数，别用 double

    @Field(type = FieldType.Keyword)
    public List<String> tags;          // 标签数组，逐元素按 keyword 处理

    @Field(type = FieldType.Date, format = DateFormat.date_time)
    public Instant createdAt;
}

// 定义数据访问接口 
// 两个泛型：Article 是实体类型，String 是主键类型
public interface ArticleRepository extends ElasticsearchRepository<Article, String> {

    // 方法名 Spring 自动翻译：category = ? AND status = ?，分页交给 Pageable
    Page<Article> findByCategoryAndStatus(String category, String status, Pageable pageable);

    // 查询 id 在这一批里的文档
    List<Article> findByIdIn(List<String> ids);
}

// 写业务类 
@Service 
public class ArticleService {

  // 两个依赖：Spring 通过构造方法自动注入
    private final ArticleRepository repository;
    private final ElasticsearchOperations ops;
    public ArticleService(ArticleRepository repository, ElasticsearchOperations ops) {
        this.repository = repository;
        this.ops = ops;
    }

    // 新增 / 全量保存：简单 CRUD，直接用 repository 

    public Article save(Article a) {
        return repository.save(a); // 按 id 存在就覆盖整篇，不存在就新增
        // 注意：这是【整篇覆盖】，只 new 一个带 id 的对象来 save，其它字段会被冲成 null
    }

    public Article getById(String id) {
        return repository.findById(id).orElse(null); // 返回 Optional，业务里自己判空
    }

    public void delete(String id) {
        repository.deleteById(id);
    }

    // 组合搜索：复杂查询用 NativeQuery，逐行看注释
    // 入参：关键词、分类、状态、页码(从0开始)、每页条数
    public List<Article> search(String keyword, String category, String status,
                                int page, int size) {

        var bool = new BoolQuery.Builder();

        // filter：必须满足，但【不算分】，还能被缓存。业务边界条件一律放这
        bool.filter(f -> f.term(t -> t.field("status").value("published"))); // 只搜已发布
        if (category != null && !category.isBlank())
            bool.filter(f -> f.term(t -> t.field("category").value(category))); // keyword 用 term 精确匹配

        // must：参与算分。关键词同时搜标题和正文，title 权重×3
        if (keyword != null && !keyword.isBlank())
            bool.must(m -> m.multiMatch(mm -> mm.fields("title^3", "content").query(keyword)));

        // 把 bool 包成 Spring 的查询对象，带上分页和排序
        var q = NativeQuery.builder()
                .withQuery(bool.build()._toQuery())
                .withPageable(PageRequest.of(page, size))                 // 页码从 0 开始
                .withSort(s -> s.score(sc -> sc.order(SortOrder.Desc)))  // 先按相关度分
                .withSort(s -> s.field(f -> f.field("_doc").order(SortOrder.Asc))) // 同分兜底
                .build();

        // 执行查询，把 SearchHit 里的文档取出来
        return ops.search(q, Article.class).getSearchHits().stream()
                  .map(h -> h.getContent()).toList();
    }

    // 局部更新：只改 score，别用 save（会把别的字段冲没）

    public void updateScore(String id, long newScore) {
        Document patch = Document.create();
        patch.put("score", newScore);
        ops.update(UpdateQuery.builder(id).withDocument(patch).build(),
                   IndexCoordinates.of("articles"));
    }

    // 深分页 search_after：别用大 from/size，窗口默认只 1 万 
    // 第一页 after 传 null，之后传上一页最后一条的 sortValues
    public List<Article> searchAfter(List<Object> after, int size) {
        var q = NativeQuery.builder()
                .withQuery(w -> w.term(t -> t.field("status").value("published")))
                .withPageable(PageRequest.of(0, size))
                .withSort(s -> s.field(f -> f.field("score").order(SortOrder.Desc)))
                .build();
        if (after != null) q.setSearchAfter(after);
        var hits = ops.search(q, Article.class);
        return hits.getSearchHits().stream().map(h -> h.getContent()).toList();
        // 想拿"下一页游标"就：hits.getSearchHits().getLast().getSortValues()，传回前端做游标
    }

    // 聚合：按分类统计数量和平均分数 

    public void aggregateByCategory() {
        var q = NativeQuery.builder()
                .withQuery(w -> w.term(t -> t.field("status").value("published")))
                .withMaxResults(0) // size=0：只要统计结果，不返回文档列表
                .withAggregation("cats", Aggregation.of(a -> a
                        .terms(t -> t.field("category").size(20)))) // 按 category(keyword) 分桶
                .build();

        var hits = ops.search(q, Article.class);
        var aggs = (ElasticsearchAggregations) hits.getAggregations();
        var buckets = aggs.get("cats").aggregation().getAggregate().sterms().buckets().array();
        for (var b : buckets) {
            String cat = b.key().stringValue();
            long count = b.docCount();
        }
    }
}

// 暴漏成HTTP接口 
@RestController
@RequestMapping("/articles")
public class ArticleController {

    private final ArticleService service;
    public ArticleController(ArticleService service) { this.service = service; }

    @GetMapping("/{id}")
    public Article get(@PathVariable String id) { return service.getById(id); }

    @PostMapping
    public Article create(@RequestBody Article a) { return service.save(a); }

    // GET /articles/search?keyword=ES&category=tech&page=0&size=10
    @GetMapping("/search")
    public List<Article> search(@RequestParam(required = false) String keyword,
                                @RequestParam(required = false) String category,
                                @RequestParam(defaultValue = "0") int page,
                                @RequestParam(defaultValue = "10") int size) {
        return service.search(keyword, category, "published", page, size);
    }
}
