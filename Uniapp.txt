// 应用生命周期 
onLaunch --> uni-app 应用初始化完成时触发, 全局只触发一次 一般用于查看用户是否授权、获取用户设备信息等 
onShow --> 应用启动或从后台进入前台时触发, 可以触发多次 一般用于重新进入应用的消息提示或者数据刷新 
onHide --> 监听应用从前台进入后台 一般用于退出应用时的消息提示 
onError --> 应用报错时被触发 用于监测并处理错误 

前后台定义: 当我们离开应用时, 应用不会被直接销毁, 而是进入后台, 当我们再次进入应用时, 应用就会从后台进入前台 
什么时候会被真正销毁呢? 当应用进入后台超过一定时间, 或者系统资源占用过高, 应用才会被真正销毁, 再次打开就是重新初始化启动应用

// 页面栈 
用于存储已经打开、还没有销毁的页面; 新页面入栈, 返回就出栈, 栈最多存10个页面 

// 五大导航跳转
uni.navigateTo({url}) // 不能跳 tabBar url可带查询参数 页面栈最多10层 --> navigate
uni.redirectTo({url}) // 不能跳 tabBar 旧页面销毁, 返回键不会回到上一页 --> redirect
uni.reLaunch({url})   // 可以跳 tabBar url 可带参 返回键直接退出小程序 --> reLaunch  
uni.switchTab({url})  // 只能跳 tabBar url 不能带参 --> switchTab 
uni.navigateBack({delta})  // delta 代表返回上N页 --> navigateBack 

// uni.request --> 建议手动封装四大请求方法 
uni.request({
  url: 'url',    // 允许带手动拼接查询参数, 但是框架不会对这个进行自动编码, 不建议 
  method: 'GET', // POST PUT DELETE 
  header: {},
  timeout: 6000,
  data: {
    key: 'value' // 对于 GET data为查询参数, 对于 POST PUT DELETE data为请求体 --> 框架自动编码 
  },
  success(res) {
    console.log(res.data, res.statusCode, res.header, res.cookies)
  }
})
